# Deploy it for free (step by step)

You'll use three free services:

| Part | Service | What it does |
|---|---|---|
| Database | **Neon** | Hosts your Postgres database |
| Backend | **Render** | Runs the FastAPI app in Docker |
| Frontend | **Vercel** | Serves the React site |

Plus **GitHub Actions** to send the daily alerts.

It takes about 30 minutes. Do the steps in order, because each one needs a value from the step before.

```
Browser ──► Vercel (React) ──► Render (FastAPI) ──► Neon (Postgres)
                                    ▲
             GitHub Actions ────────┘  (every weekday 6:30 pm IST: "run the alerts")
```

---

## Step 0: Put the code on GitHub

```bash
cd portfolio-risk-copilot
git init
git add .
git commit -m "Portfolio Risk Copilot"
```

Create an **empty** repo on github.com (no README), then:

```bash
git remote add origin https://github.com/<your-username>/portfolio-risk-copilot.git
git branch -M main
git push -u origin main
```

The **CI** workflow runs automatically. Check the **Actions** tab. Both jobs should show a green tick. It runs all tests on both SQLite and Postgres.

## Step 1: Database on Neon

1. Sign up at **neon.tech** (GitHub login works).
2. Create a project:
   - Name: `risk-copilot`
   - Postgres version: 16 or newer
   - Region: **AWS Asia Pacific (Singapore)**. Keep the database and backend in the same region. Every page load makes several database calls, so distance adds up.
3. On the dashboard, click **Connect**. Turn **off** "Connection pooling" so you get the direct connection string. It looks like:
   ```
   postgresql://neondb_owner:AbC123@ep-cool-name-123456.ap-southeast-1.aws.neon.tech/neondb?sslmode=require
   ```
4. Copy it. This is your `DATABASE_URL`.

**You don't need to create any tables.** The app creates them itself on its first start (see "How the database gets set up" below).

---

## Step 2: Backend on Render

1. Sign up at **render.com** with GitHub.
2. Click **New → Blueprint** and choose your repo. Render reads `render.yaml` from the repo.
3. It asks for the values marked `sync: false`:

   | Key | What to enter |
   |---|---|
   | `DATABASE_URL` | The Neon string from Step 1, pasted exactly as is |
   | `CORS_ORIGINS` | Type `http://localhost:5173` for now. You'll change it in Step 4. |
   | `ADMIN_EMAILS` | Your email. When you sign up with it, you can see usage stats. |
   | `GOOGLE_API_KEY` | Free key from https://aistudio.google.com/apikey (or leave empty for basic mode) |
   | `GROQ_API_KEY` | Backup AI. Free key from https://console.groq.com/keys (or leave empty) |
   | `TELEGRAM_BOT_TOKEN` | From @BotFather (or leave empty) |

   `JWT_SECRET` and `CRON_SECRET` are generated by Render automatically.

4. Click **Apply**. The first build takes about 5 minutes.
5. When it's live, open `https://<your-service>.onrender.com/api/health`. You should see:
   ```json
   {"status":"ok","database":"ok", ..., "llm_provider":"gemini","llm_backup":"groq", ...}
   ```
   `"database":"ok"` means the app reached Neon and created the tables. `llm_provider` and `llm_backup` show which AI keys were found.
6. Also try `https://<your-service>.onrender.com/docs`. This is the interactive API page.

**Copy your Render URL.** You need it next.

> **If the deploy fails,** open the **Logs** tab on Render. The most common causes:
> - `JWT_SECRET is missing or too short`: the generated value didn't apply. Set any random 48+ character value by hand.
> - `could not translate host name` or `password authentication failed`: the `DATABASE_URL` was copied wrong. Copy it again from Neon.

## Step 3: Frontend on Vercel

1. Sign up at **vercel.com** with GitHub.
2. **Add New → Project** → import your repo.
3. Settings:
   - **Root Directory:** `frontend`
   - Framework: Vite (detected automatically)
   - **Environment Variable:** `VITE_API_URL` = your Render URL, e.g. `https://risk-copilot-api.onrender.com`
4. Click **Deploy**. Copy your site URL, e.g. `https://risk-copilot.vercel.app`.

> `VITE_API_URL` is baked into the site when it builds. If you change it later, redeploy on Vercel.

---

## Step 4: Connect them (CORS)

Your browser blocks the site from calling the backend unless the backend allows it. This rule is called **CORS**.

1. Render → your service → **Environment**.
2. Set `CORS_ORIGINS` to your Vercel URL, exactly: `https://risk-copilot.vercel.app` (no `/` at the end).
3. Save. Render restarts the app.

Now open your Vercel site, sign up with your admin email, and upload `sample_data/zerodha_kite_holdings.csv`. 🎉

> Vercel also makes "preview" URLs for each push. Those won't work with the backend, because only your main URL is in `CORS_ORIGINS`. That's expected.

---

## Step 5: Daily alerts with GitHub Actions

The free Render plan **sleeps after 15 minutes** with no visitors, so the app's own timer can't run. Instead, GitHub calls the app every weekday at 6:30 pm IST.

1. On Render → Environment, copy the value of `CRON_SECRET`.
2. On GitHub → your repo → **Settings → Secrets and variables → Actions → New repository secret**. Add two:
   - `API_URL` = your Render URL (no `/` at the end)
   - `CRON_SECRET` = the value you copied
3. Test it: **Actions** tab → **Daily alerts** → **Run workflow**. It should finish green and print something like `{"users_checked":1,"alerts_created":2}`.

> GitHub pauses scheduled workflows in repos with no commits for 60 days. Push any small change to keep it running.

## Step 6: Use NSE's full stock list (recommended)

The app ships a starter list of ~130 NSE stocks. For all 500 with NSE's official industries, run this **on your laptop** (Render's disk is wiped on every deploy, so don't run it there):

```bash
cd backend
python -m scripts.update_stock_list
git add app/data/nifty500.csv
git commit -m "Add NSE Nifty 500 list"
git push
```

Render redeploys with the full list. Re-run it every six months, when NSE updates the index.

## How the database gets set up

You never run SQL by hand. When the app starts, it runs **migrations**.

A **migration** is a small numbered script that creates or changes tables. Example: `0001_initial.py` creates `users`, `holdings`, `price_bars` and `alerts`. The tool that runs them is **Alembic**.

Alembic keeps a tiny table called `alembic_version` that records which migrations already ran. On every start:

```
App starts → Alembic checks alembic_version → runs only NEW migrations → app is ready
```

So it's safe to restart or redeploy any number of times.

**When you change the database later** (for example, adding a column):

```bash
cd backend
# 1. Edit app/models.py
# 2. Generate a migration from your change:
alembic revision --autogenerate -m "add notes to holdings"
# 3. Open the new file in migrations/versions/ and check it looks right
# 4. Commit and push. Render redeploys and the app applies it on start.
```

CI runs `alembic check`, which fails if you change `models.py` but forget step 2.

**Tables:**

| Table | What's in it |
|---|---|
| `users` | Email, hashed password, role (user/admin), Telegram chat ID |
| `holdings` | Each user's stocks: symbol, quantity, average price, sector |
| `price_bars` | Saved daily closing prices, shared by all users. Each stock is downloaded once, not once per user. |
| `alerts` | Alerts per user, with a "dedupe key" so the same alert is never sent twice |
| `alembic_version` | Which migration the database is on |

## What to expect on free plans

| Thing | What happens | Is it a problem? |
|---|---|---|
| **First visit after a break** | Render takes about a minute to wake up. The site shows "Can't reach the server... try again". | Normal on free plans. Open the site a minute before you demo it. |
| **First portfolio load** | Downloads ~7 years of prices per stock from Yahoo. Takes a few seconds once, then it's cached. | Fine |
| **Yahoo Finance** | Yahoo sometimes blocks cloud servers. Then the dashboard shows "No price data for X". | The app retries 10 minutes later. Prices already saved keep working. |
| **Memory** | I measured about 290 MB peak with 20 users at once. Render free gives 512 MB. | Fine |
| **Neon free** | The database pauses when idle and wakes on the next query (adds about a second). | Fine. The app reconnects automatically. |

**Don't use Render's free Postgres.** Render deletes free databases 30 days after creation. Neon's free database doesn't expire.
